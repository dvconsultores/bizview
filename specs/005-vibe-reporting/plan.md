# Implementation Plan: Vibe Reporting

**Branch**: `005-vibe-reporting` | **Date**: 2026-09-29 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/005-vibe-reporting/spec.md`

## Summary

Make every integration and report a Spec Kit spec. Customers (or implementers) work in a private
**workspace** repository created by `bizview init`: Spec Kit with the Bizview preset (integration
and report templates) and extension (`/bizview-validate`, `/bizview-describe`, mandatory
`after_implement` validation hook), agent rules, and a validator that writes a checksum lock. The
AI writes only declarative artifacts (`integration.yaml` + read-only SQL / request definitions;
`report.yaml`). The installation mounts the workspace, validates, and applies it atomically
(step-up, audit, rollback). A worker runs integrations into engine-owned dataset schemas; a generic
report engine serves KPIs, trends, rankings, PDF, and optional AI narratives restricted to spec-
declared aggregates. The in-app assistant is dropped; feature 001 is superseded (research R10).

## Technical Context

**Language/Version**: Python 3.12+ (backend, worker, CLI), TypeScript 5 (frontend)

**Primary Dependencies**: features 002–004 + `sqlglot` (read-only SQL enforcement), `jsonschema`
(artifact schemas), `PyYAML`, `polars` (extraction typing/checks), `APScheduler` 3 (worker),
`reportlab` (PDF); the trend chart is a small inline SVG component (no chart library: smaller
mobile bundle, Safari 14-safe); GitHub Spec Kit 1.x (`specify-cli`) for workspaces

**Storage**: `public` (migration `0004_vibe_reporting`) + engine-owned `ds_<integration>` schemas

**Testing**: pytest (validator rules and schemas, SQL safety corpus, lock/apply/rollback, runner
with the Customer B origin read-only and REST/SOAP stubs, report engine periods/comparisons,
narrative input capture, token/describe); CLI tests on a generated workspace; Playwright for the
report renderer and workspace admin at 320/375 px

**Target Platform**: installations (feature 003) with a new `worker` service; report authors'
machines (CLI, Spec Kit, any agent)

**Project Type**: web application + worker + CLI + Spec Kit preset/extension

**Performance Goals**: report view p95 < 1 s (SC-004); spec-to-dashboard < 1 h (SC-002)

**Constraints**: no customer logic in product code; SQL read-only; no credentials or row values in
the workspace or AI inputs; databases external

**Scale/Scope**: tens of integrations and reports per installation; datasets up to tens of
millions of rows (materialised daily aggregates)

## Project Structure

```text
cli/                              bizview-cli (init, validate, describe) + shared schemas/rules
├── pyproject.toml
└── bizview_cli/{__main__,init,validate,describe,sqlsafety}.py, schemas/*.json
    └── workspace_template/       shipped as package data, installed by `bizview init`
        ├── preset/               Spec Kit preset "bizview": spec/plan/tasks templates,
        │                         speckit.specify command override
        ├── extension/            Spec Kit extension "bizview": validate/describe commands,
        │                         mandatory after_implement hook
        └── files/                constitution, CLAUDE.md, AGENTS.md, copilot instructions,
                                  README.md, bizview.yaml, .gitignore
backend/app/
├── workspace/service.py          mounted folder → validation (+ live checks) → versions,
│                                 apply / rollback, dashboard sync
├── engine/{datasets,extract,runner,report,periods,narrative}.py
├── reports/pdf.py                ReportLab PDF from the JSON view payloads
├── sources/describe.py           structure-only describe (PostgreSQL / REST / SOAP)
├── api/{workspace,reports,tokens}.py (+ describe in api/sources.py; integrations in workspace.py)
└── worker.py                     python -m app.worker: scheduler + run requests (same image)
frontend/src/pages/{ReportView,admin/Workspace,admin/Integrations,admin/Tokens}.tsx
frontend/src/components/report/{KpiGrid,TrendChart,RankingTable,DataTable,PeriodPicker,Narrative}.tsx
deploy/: compose + installer mount ./workspace (read-only) into backend and worker
```

**Structure Decision**: the worker is the backend image with another entry point (shares
connectors, crypto, engine). The CLI shares the validation module with the backend by vendoring
the same `bizview_cli` package as a backend dependency (path dependency).

## Complexity Tracking

| Item | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| Lock checksums + DB copy of the applied version | "no spec, no run" must hold even if mounted files change | trusting files at read time allows unvalidated edits to run |
| Engine-owned dataset schemas | customer datasets are defined by specs, not product migrations | Alembic per customer = customer code in the product |
