# Implementation Plan: Import limits that account for project images, and import as the only way in

**Branch**: `049-import-limits-assets` (worked on `main`, no branch created) · **Date**: 2026-11-01 ·
**Spec**: [spec.md](./spec.md)

## Summary

Two defects, one root cause. 031 gave the import a single budget ("400 files, 2 MB per file, 20 MB"),
and 044 added `assets/**` without giving images a budget of their own — so every image an author ships
is charged to the artifact allowance, and a project with a logo set can never be imported. Separately,
the product still offers manual project creation, which contradicts the standing rule that a project
enters Bizview only through import (constitution, Constraints).

This plan turns the budget into a first-class concept: a path is classified into **artifacts** or
**assets** by the shared layout module, each class has its own file count, per-file size and total,
the refusal names the class that was exceeded, the browser reports both tallies before uploading, and
the manual-creation affordance and endpoint are removed.

## Technical Context

**Language/Version**: Python 3.12 (backend, CLI), TypeScript 5 / React 19 (frontend)
**Primary dependencies**: FastAPI + SQLAlchemy 2 + Alembic, psycopg 3, PyYAML; React + Vite + Vitest; no
zip library in the frontend (a central-directory reader is written and unit-tested)
**Storage**: PostgreSQL (product schema, Alembic); project files on disk under `PROJECTS_DIR`
**Testing**: pytest (backend, against a real PostgreSQL test schema), pytest (CLI), Vitest (unit),
Playwright (e2e)
**Target Platform**: Linux server (containers) + mobile-first web client
**Project Type**: web application (backend + worker + SPA) with a shared CLI/library
**Performance Goals**: the pre-flight reads only the archive's index — no decompression, no upload of
a rejected file; the server's tally is one pass over the archive's entries
**Constraints**: text-only artifacts, byte-sniffed images, sanitised SVG, no path escaping the project
folder, nothing half-imported on refusal (031 security, unchanged)
**Scale/Scope**: projects up to ~2 400 files (400 artifacts + 2 000 assets), zips up to 45 MB

## Phase 0 — Research (see [research.md](./research.md))

Nine decisions, each with the alternative that was rejected:

- **R1** a path is classified into a budget, and the classification is the layout's (one table, one owner).
- **R2** the six numbers are installation settings: a DB singleton with NULL = inherit from the env
  defaults, so an operator's `PROJECT_MAX_MB` keeps working and a super user can raise them in the app.
- **R3** the shared tally lives in the CLI package and the backend imports it, because the layout is the
  single source (constitution, Constraints).
- **R4** the zip-bomb protection counts each entry against its own budget; the structural entry cap
  becomes the sum of both, because count is not what protects against a bomb (size and ratio are).
- **R5** "harmless" versus "disallowed" is decided by extension **and** bytes, so a `.js` fails while a
  `README.md` is skipped.
- **R6** the pre-flight reads the archive's index in the browser — no dependency added.
- **R7** the creation endpoint answers `410 Gone` (kept, documented, unactionable) rather than 404, so an
  old client learns why; `/slug` is removed with its only caller.
- **R8** the export is unchanged, and re-importing an export is the acceptance test that both budgets agree.
- **R9** the per-file artifact limit becomes 2 MB as the spec states, from one shared constant, so the
  CLI's 512 KB check cannot disagree with the server.

## Complexity Tracking

| Item | Why it is not simpler |
|---|---|
| A DB singleton for the limits | The alternative (env-only) cannot satisfy "super user editable in the app". NULL columns keep the env default working, so no operator is surprised |
| Two tally implementations (Python and TypeScript) | The pre-flight must run before any byte is uploaded, so it cannot ask the server. The server re-checks, so the browser's copy advises and never decides |
| A new CLI command (`import --dry-run`) | The spec asks the CLI to report the server's numbers for a zip, which `validate` (a folder, a workspace) cannot do |

## Risks

- **The two tallies can drift.** Mitigated: the same fixture is tallied by both, and a test asserts the
  CLI's numbers equal the server's (SC-005).
- **Raising the per-file artifact limit to 2 MB** widens what a YAML may be. Mitigated: every artifact is
  still parsed and schema-checked; this is a size gate, not a content gate.
- **A leftover caller of the removed endpoint** would break. Mitigated: a repo-wide grep, the e2e suite,
  and `POST /api/projects` answering 410 with a documented code instead of vanishing.
