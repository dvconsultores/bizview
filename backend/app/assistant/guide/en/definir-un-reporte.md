# Define a report

## What it is for

It explains what `reports/<id>/report.yaml` holds: the file that defines a dashboard, where it
reads from, what it measures and how it looks.

## Who can use it

Only the **Superuser**; the agent usually writes it with `/speckit-implement`.

## How to

Fields:

- `title` and `description` (and optional `title_en`, `description_en` for English).
- Data: `uses` (aliases of integration datasets) or `direct` (source and tables of a direct report,
  with `cache_seconds`). The spec states it in its `**Modo**:` line.
- `date`: the date column the periods use.
- `metrics`: each metric with its exact `sql` or a `formula` of other metrics, its format and
  whether higher or lower is better.
- `dimensions`: the fields to group and filter by.
- `views`: `kpis`, `trend`, `ranking` and `table`; a view may declare an `id`.
- `filters`, `periods` and `compare`: the dashboard's controls and their defaults.
- `access`: the roles that see it.
- `pdf`: `enabled`, which enables the export; `layout.pdf` sets the orientation and the views.
- `layout` (optional): `web` and `pdf`, the dashboard's and the PDF's composition; without them
  nothing changes.
- `ai_narrative` (optional): the AI summary built from totals.

The layout:

- `layout.web`: `gutter` (`sm`, `md` by default, or `lg`) and `components` (at least one). Every
  component carries its own `id` and a `span` of 1 to 12 columns of the desktop 12-column grid (12
  by default); on a phone they stack in the same order, which is the reading order. Without
  `layout.web` the dashboard composes itself.
- `layout.pdf`: `page` (`size` `a4` or `letter`, `orientation` `portrait` or `landscape`, and
  `margins` 5–40 mm), `overflow` and `blocks`. `overflow: continue` carries the table on to the
  next page with its header; `overflow: truncate` cuts it and says how many rows are left out.
  Without `layout.pdf` the PDF uses the fixed template as before.

The link is by `id`, never by position and never by type; without an `id`, a view cannot be
referenced.

```yaml
views:
  - {id: resumen, type: kpis, metrics: [total_facturado, facturas]}
layout:
  web:
    components:
      - {id: kpis, type: kpi, view: resumen, metric: total_facturado, span: 12}
```

Web components, one of each type (no `view`: `text`, `spacer`, `filters`):

```yaml
components:
  - {id: k1, type: kpi, view: resumen, metric: total_facturado, delta: previous_period}
  - {id: c1, type: line, view: diaria, x: day, series: [total_facturado], colors: [series1], span: 8}
  - {id: c2, type: area, view: diaria, x: day, series: [total_facturado]}
  - {id: c3, type: bar, view: estados, x: estado, series: [total_facturado], orientation: horizontal, span: 4}
  - {id: c4, type: pie, view: estados, category: estado, value: total_facturado, top_n: 6}
  - {id: c5, type: donut, view: estados, category: estado, value: total_facturado}
  - {id: t1, type: table, view: detalle, columns: [estado, facturas], totals: true, sort: {by: facturas, dir: desc}, page_size: 25}
  - {id: n1, type: text, text: "Provisional figures.", style: caption, font_name: serif}
  - {id: f1, type: filters, only: [estado]}
  - {id: s1, type: spacer, size: md}
```

Fields per type:

- `kpi`: `metric`, `delta` (`previous_period` or `none`) and `sparkline`.
- `line` and `area`: `x` (an ordered dimension or a grain) and `series`.
- `bar`: as above, plus `orientation` (`vertical` or `horizontal`) and `stacked` (two series).
- `pie` and `donut`: `category`, `value`, `top_n` from 2 to 12 (6 by default) and `other_label`.
- `table`: `columns`, `totals`, `sort` (`by`, `dir`) and `page_size` 5 to 200.
- `text`: `text` from 1 to 500 characters, `text_en`, `style` (`heading`, `paragraph`, `caption`)
  and `font_name`.
- `filters`: `only`, with the `filters` it shows.
- `spacer`: `size` (`sm`, `md` or `lg`).

PDF blocks, one of each type (no `view`: `header`, `text`, `page_break`, `footer`):

```yaml
blocks:
  - {id: cabecera, type: header, title: true, subtitle: true, period: true, logo: true, logo_role: brand}
  - {id: kpis, type: kpi_row, view: resumen, items: [total_facturado, facturas], delta: true}
  - {id: grafico, type: chart, view: diaria, kind: line, x: day, series: [total_facturado], height_mm: 60}
  - {id: tabla, type: table, view: detalle, columns: [estado, facturas], widths: [3, 1], totals: true, overflow: truncate}
  - {id: nota, type: text, text: "Internal document.", align: center, font_name: mono}
  - {id: salto, type: page_break}
  - {id: pie, type: footer, generated_at: true, page_numbers: true, legal: "Document generated by BizView."}
```

Fields per type:

- `header`: `title`, `subtitle`, `period`, `logo`, `logo_role` (`brand` or `none`).
- `kpi_row`: `view`, `items` and `delta`.
- `chart`: `kind` (as the web charts) with `x` and `series`, or `category` and `value`, plus
  `height_mm` from 30 to 200 (60 by default) and `top_n`.
- `table`: `view`, `columns`, `widths` (one weight per column), `totals` and `overflow`.
- `text`: `text`, `text_en`, `style`, `font_name` and `align` (`left`, `center` or `right`).
- `page_break`: a new page.
- `footer`: `generated_at`, `page_numbers` and `legal` (up to 200 characters).

## Options

- Labels can have an English version (`label_en`) shown to people using BizView in English.
- To be ready to apply, the report needs `pdf.enabled: true`, dimensions and filters.
- Colours are roles, never literals: `primary`, `positive`, `negative`, `neutral`, `muted` and
  `series1` to `series8`; the installation's theme and branding resolve them.
- Fonts are named (`sans`, `sans_bold`, `serif` and `mono`), and `font_name` is only accepted on a
  `text` component or block.
- The English versions of texts are `text_en`, `other_label_en` and `legal_en`.
- A layout carries no addresses and no paths: the logo uses the `logo_role`.
- `bizview validate` checks the layout with the same schema the agent uses.
- The complete example is `reports/facturas-dia/report.yaml`.
